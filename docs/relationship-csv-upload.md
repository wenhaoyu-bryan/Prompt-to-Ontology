# Relationship CSV Upload

## Why This Exists

Phase 35 added object CSV import. Phase 36 extends this to relationship CSV import, completing the custom ontology build loop: objects first, then relationships between them.

## Supported Link Types

| Link Type | Source | Target |
|---|---|---|
| CONTAINS | PetFoodProduct | Ingredient |
| MADE_BY | PetFoodProduct | Brand |
| TARGETS_SPECIES | PetFoodProduct | Species |
| SUITABLE_FOR | PetFoodProduct | LifeStage |
| SIMILAR_TO | PetFoodProduct | PetFoodProduct |

`TRIGGERS_RISK` is generated by the rule engine and is not available for direct upload.

## Relationship CSV Workflow

```text
1. Import object CSV files first (products, ingredients, etc.)
2. Approve and apply objects to the graph
3. Open Data Pipeline → Upload Custom CSV → Relationship CSV
4. Upload relationship CSV
5. Select target link type (e.g. CONTAINS)
6. Map source ID column and target ID column
7. Optionally select property columns (e.g. amount, unit)
8. System validates endpoints against the graph
9. Preview candidate links
10. Create Import Plan
11. Submit to Review Queue
12. Approve and apply relationship items
```

## Required Columns

Minimum: a source ID column and a target ID column that match existing object IDs in the graph.

Optional: additional columns mapped as relationship properties.

## Endpoint Validation

Before creating an Import Plan, the system validates each row:

- Source ID exists in the graph
- Target ID exists in the graph
- Source node has the expected object type label
- Target node has the expected object type label

Errors (missing endpoints) prevent Import Plan creation until fixed. Warnings (wrong type, duplicates) are flagged for review.

## Review Queue Integration

Relationship items appear as `IMPORT_LINK_CANDIDATE` type with metadata:

```json
{
  "source_type": "custom_csv",
  "import_type": "relationship",
  "filename": "product_ingredients.csv",
  "link_type": "CONTAINS",
  "source_row_index": 0
}
```

## Example: CONTAINS

```csv
product_id,ingredient_id,amount,unit
custom_pf_001,ing_chicken,20,percent
custom_pf_001,ing_taurine,1200,mg/kg
custom_pf_002,ing_salmon,35,percent
```

## Example: MADE_BY

```csv
product_id,brand_id
custom_pf_001,brand_example
custom_pf_002,brand_example
```

## Known Limitations

- Endpoint validation requires Neo4j to be running with the objects already applied
- No auto-creation of missing endpoint nodes from relationship CSV
- Relationship properties are not validated against the schema definition
- Large CSV files may be slow due to per-row Neo4j validation queries
